
## -- Steps --

1) Planning
2) Requirement Analysis
3) Design
4) Implementation
5) Testing
6) Deployment
7) Maintenence


### 1- Planning

This is where the application is defined, what it will do (e.g login system, dashboard, etc)


### 2- Requirement Analysis

This is where the application requirements are defined (e.g login page will have username/password fields, login will have correct validation, etc)


### 3- Design

This is where the programming language, frameworks and UML diagrams are defined


### 4- Implementation

This is where the application is developed


### 5- Testing

This is where unit testing, integration testing, user testing, etc will happen


### 6- Deployment

The system will be deployed and installed in a customer's premises


### 7- Maintenance

Ongoing updates to fix potential bugs / improve application




## -- Waterfall Model -- (Start -To-Finish)

A linear, sequential approach where each phase must be complete before the next begins. 

- Development flows in only one direction
- One phase cannot be started until the previous phase is completed
- Each phase is completed before moving on
- There should be no requirement changes, mistake sor unexpected factors
- It should be used when:
	- Requirementss are not changing frequently
	- The project is simple and short
	- Requirements are clear
	- Environment is stable


**Problems:**

- Additional features need to be planned out as they can't be added after the development phase is completed - it's too dificult and time-consuming to make significant changes

- Testing phase may happen months after development has completed, if a significant bug or design flaw is discovered the team may need to revisit previous phases
-
- Resources may be misallocated, such as developers underestimatd the complexity of testing, therefore resulting in overspending or rushed testing leading to a poor final product


**Advantages:**

- Simple and easy to understand / use
- Phases are processed and completed one at a time
- Works well for smaller projects with less requirements that are very well understood

**Disadvantages:**

- Any problems in any part of the proccess affects the whole project process and must be checked
- No working software is produced until later during the life-cycle
- Not appropriate for large projects
- Inflexible model that is difficult for any requirement changes
